🎓 LEARNINGS & BEST PRACTICES

1. Metrics Design:
   • Use histograms for latency (with appropriate buckets)
   • Use counters for events (monotonically increasing)
   • Use gauges for current state (can go up/down)
   • Label cardinality matters - avoid high-cardinality labels

2. Benchmarking:
   • Establish baselines before optimization
   • Run benchmarks in consistent environment
   • Track performance over time
   • Set realistic budgets based on use cases

3. Documentation:
   • Code examples in multiple languages increase adoption
   • Interactive docs (Swagger) complement written guides
   • Keep docs close to code (same repo)
   • Version documentation with releases

4. Coverage:
   • Target 70-80% for business logic
   • Exclude UI components (tested separately with E2E)
   • Focus on critical paths
   • Use coverage to find untested edge cases
